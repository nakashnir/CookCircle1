IMPLEMENTATION REQUIREMENTS
====================================================

1. Inspect the current codebase first
Before changing anything, inspect:

Then implement the smallest safe patch.

2. Backend auth
Add real local auth using email + password.

Required endpoints, names may follow existing API style:
- POST /api/auth/register
- POST /api/auth/login
- POST /api/auth/logout
- GET /api/auth/me

If the existing code already has /api/session/me or similar, you may keep compatibility aliases, but the final behavior must support real email/password login.

Register:
- Accept name, email, password, optionally phone/city if current user model supports it.
- Validate email format minimally.
- Validate password length, minimum 8 chars.
- Reject duplicate email.
- Store password as hash, never plain text.
- Return safe user object only.

Login:
- Accept email + password.
- Verify password against passwordHash.
- Set server session/cookie.
- Return safe user object only.

Logout:
- Clear session/cookie.

Me:
- Return current authenticated user if logged in.
- Return 401 if not logged in.

Password hashing:
- Prefer bcryptjs if already installed.
- If not installed and avoiding dependency is better, use Node crypto scrypt/pbkdf2 with salt.
- Do not store plain passwords.

Session:
- Use the current cookie/session structure if possible, but make it real.
- Cookie should be httpOnly.
- sameSite should be reasonable for Replit deployment.
- secure should be enabled only when compatible with deployment/runtime.
- Session must not auto-default anonymous users to user 1.

3. Authorization enforcement
Require authenticated user for all user-specific mutations:
- create donation
- edit donation
- delete/cancel/reopen donation
- create pickup request
- approve/decline/cancel/complete pickup request
- create review
- profile updates if any

Do not allow unauthenticated users to mutate app state.

Public read endpoints may remain public:
- list available donations
- view public donation details if the app currently allows it

Important:
Existing ownership rules must remain:
- A donor can manage only their own donations
- A requester can manage only their own requests where appropriate
- Donor can approve/decline requests for their own donations
- Review only after completed request, no duplicate review

4. User object safety

Create a safeUser helper if needed:

- avatar/profile fields if present

But never passwordHash.
